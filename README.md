# MailBot RIS-25-2

Пересылка писем из Mail.ru в Telegram-группу через GitHub Actions.

## Что делает бот

- Подключается к Mail.ru по IMAP и проверяет `INBOX`.
- Превращает HTML-письмо в читаемый текст: сохраняет абзацы, списки и URL ссылок, убирает теги, стили и скрипты.
- Отправляет письма в группу Telegram вместе с файлами и inline-вложениями. Если отдельный файл слишком большой или Telegram не подтвердил его отправку, бот всё равно доставляет текст письма и отдельное заметное предупреждение со списком недоставленных файлов и просьбой открыть письмо в Mail.ru. Если найден файл больше лимита, бот отправляет только текст письма и предупреждение, пропуская все вложения этого письма.
- Делит длинный текст максимум на `MAX_TEXT_MESSAGES` сообщений. Если частей больше, отправляет начало письма в группу, а весь текст — файлом `email_body.txt`.
- Проверяет ответы Telegram API. Письмо не переносится в архив, пока не доставлены текст и, при необходимости, предупреждение о недоставленных файлах.
- После успешной отправки переносит письмо в `SeenByBot`. Письма от `SKIP_SENDERS` сохраняет в `IgnoredByBot`.
- Создаёт эти папки, если их ещё нет.

Папки с обработанными письмами остаются на почтовом сервере. Для IMAP-серверов с поддержкой постоянных пользовательских флагов бот сохраняет отметку после каждой части. Это позволяет продолжить после сбоя, не пересылая уже подтверждённые Telegram части. Для архивирования используется `UID MOVE` либо `UIDPLUS`. Если сервер не поддерживает ни один вариант, бот копирует письмо в архив и помечает только его как удалённое; оно может отображаться зачёркнутым в INBOX до обычной очистки почты. Общий `EXPUNGE`, который мог бы удалить другие сообщения пользователя, бот не вызывает.

## Секреты GitHub Actions

В настройках репозитория открой **Settings → Secrets and variables → Actions** и создай четыре repository secrets:

| Имя | Значение |
|---|---|
| `EMAIL_USER` | Адрес ящика Mail.ru |
| `EMAIL_PASSWORD` | Пароль, который сейчас использует бот для IMAP; при включённой двухфакторной защите — пароль приложения |
| `TELEGRAM_TOKEN` | Токен бота от BotFather |
| `TELEGRAM_CHAT_ID` | ID группы Telegram |

Секреты не нужно записывать в `bot.py`, README или обычные переменные репозитория. Имена четырёх основных секретов совпадают с текущим workflow.

## Запуск через cron-job.org

Внешнее задание cron-job.org запускает workflow GitHub раз в 15 минут через REST API. В workflow оставлен только `workflow_dispatch`, чтобы одновременно не срабатывало встроенное расписание GitHub Actions.

Для вызова API создай fine-grained personal access token GitHub:

- Resource owner: `azimiml365085-gif`.
- Repository access: только `MailBotRIS252`.
- Repository permissions: `Actions` — `Read and write`.
- Установи срок действия токена и обновляй его до истечения.

В cron-job.org укажи:

- Метод: `POST`.
- URL: `https://api.github.com/repos/azimiml365085-gif/MailBotRIS252/actions/workflows/check_mail.yml/dispatches`.
- Заголовки:

  ```text
  Authorization: Bearer <FINE_GRAINED_TOKEN>
  Accept: application/vnd.github+json
  X-GitHub-Api-Version: 2026-03-10
  Content-Type: application/json
  ```

- Тело запроса: `{"ref":"main"}`.

Успешный запрос возвращает HTTP `200` и запускает workflow. Если cron-job.org отвечает `401 Bad credentials`, GitHub не принял токен: проверь, что заголовок `Authorization` передаётся без кавычек и что токен не истёк, не отозван и имеет доступ `Actions: Read and write` к этому репозиторию. Не публикуй токен в репозитории, скриншотах или переписке; если он стал доступен другим, отзови его и создай новый.

## Как заменить файлы в текущем репозитории

В своём репозитории замени `bot.py`, `requirements.txt` и `.github/workflows/check_mail.yml`; добавь `tests/test_bot.py`. Имена и содержимое Actions secrets менять не требуется. После коммита запусти workflow вручную один раз и проверь шаги `Run local tests` и `Run bot`.

## Дополнительные настройки

Все параметры необязательны:

| Переменная | Значение по умолчанию | Назначение |
|---|---:|---|
| `IMAP_SERVER` | `imap.mail.ru` | IMAP-сервер |
| `SKIP_SENDERS` | `security@id.mail.ru` | Адреса через запятую, которые бот не пересылает |
| `SEEN_FOLDER` | `SeenByBot` | Папка для успешно доставленных писем |
| `IGNORED_FOLDER` | `IgnoredByBot` | Папка для писем от исключённых отправителей |
| `TELEGRAM_SEND_INTERVAL` | `3.1` | Пауза между отправками, секунд |
| `MAX_TEXT_MESSAGES` | `8` | Максимум сообщений для тела одного письма до перехода на `.txt` |
| `MAX_EMAILS_PER_RUN` | `50` | Максимум писем за один запуск |
| `IMAP_TIMEOUT` | `30` | Таймаут соединения с IMAP, секунд |
| `LOG_LEVEL` | `INFO` | Уровень журналирования |

Дополнительные переменные можно передать в секции `env` шага `Run bot` в `check_mail.yml`. Секреты туда добавлять можно только через `${{ secrets.NAME }}`.

## Проверка и запуск вручную

cron-job.org запускает тесты, а затем бота каждые 15 минут. Тот же workflow можно запустить вручную через вкладку **Actions** → **Check Mail and Send to Telegram** → **Run workflow**.

Внешние Python-библиотеки не нужны. Локально запусти проверки:

```bash
python -m unittest discover -s tests -v
python bot.py
```

Для локального запуска сначала задай переменные окружения из таблицы секретов. Не добавляй файл с настоящими секретами в Git.

## Ограничения доставки

- Telegram допускает сообщения длиной до 4096 символов после разбора HTML; бот использует более короткие части, чтобы оставить место для заголовка письма. Стили CSS письма в Telegram не переносятся, но абзацы, списки и адреса ссылок остаются.
- В Telegram-группе действует ограничение на частоту сообщений. Бот ждёт между отправками и обрабатывает `retry_after` из ответа Telegram.
- Если хотя бы одно вложение превышает 50 MB, бот отправляет только текст письма, пропускает все вложения этого письма и присылает предупреждение со списком файлов, которые нужно скачать из исходного письма в Mail.ru. При неожиданном отказе Telegram бот сообщает о конкретном недоставленном файле; остальные файлы, которые Telegram принял, отправляются. После подтверждённой отправки предупреждения письмо архивируется, а недоставленные вложения не вызывают повторную отправку предупреждения при следующих запусках.
- Если Telegram не принимает текст письма или предупреждение, письмо остаётся в `INBOX`, чтобы бот мог повторить доставку при следующем запуске.
- Ни IMAP, ни Telegram не дают общей транзакции «доставить и подтвердить». Если Telegram принял сообщение, но соединение оборвалось до ответа, одна последняя часть иногда может прийти повторно. При наличии постоянных IMAP keyword-флагов подтверждённые ранее части не отправляются заново.

Лимиты указаны в [Telegram Bot API](https://core.telegram.org/bots/api) и [официальном FAQ для ботов](https://core.telegram.org/bots/faq).
